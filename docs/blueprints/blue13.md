# BLUE13 — 阶段 35~41：科学计算、可信度、可复现工作流与生态完善

## 1. 背景与目标

BLUE1~12 已建立统一仿真模型、运行时与求解器，覆盖多个物理领域、跨场耦合、数据记录、可视化、批处理、GPU 计算和扩展接口。下一阶段不再继续堆叠领域清单，而是补齐从“能运行模型”到“能高效求解、验证结果、解释误差、复现实验并稳定集成”的通用能力。

本蓝图面向 `core/compute`、`runtime`、`coupling`、`postproc`、`bindings` 及领域求解器的共同短板，新增以下能力：

1. 面向大型离散模型的稀疏矩阵与迭代线性求解器。
2. 参数估计、灵敏度分析、不确定性传播和约束优化。
3. 网格、边界区域、场数据与自适应细化的统一契约。
4. 可复现、可检查点恢复并可扩展到多进程/多节点的执行工作流。
5. 带元数据、版本与来源信息的仿真结果数据集。
6. 数值验证、收敛研究、基准测试和后端一致性检查。
7. 可安装、可发现、可兼容演进的命令行与语言绑定/插件接口。

**边界约束：** 不在本蓝图中新增大批领域物理模型；不以算法名称或功能清单代替可验证实现；已有的参数扫描、记录回放、报告、网格导入、Python 侧接口、插件和 GPU 机制作为基础设施继续完善，并通过验收测试确认其端到端行为。

## 2. 总体设计原则

- 公共能力优先沉淀在 `core`、`runtime` 或 `postproc`，领域模块仅通过稳定接口调用，不复制数值内核。
- 所有数值 API 显式声明维度、存储布局、容差、边界条件和精度；输入非法、内存不足、不收敛及后端不可用均返回带上下文的错误。
- CPU 路径作为正确性基线；并行、GPU 和分布式路径必须能通过同一组容差和物理不变量测试。
- 仿真结果记录配置、模型/插件版本、随机种子、单位、求解器设置和代码构建信息，便于追溯及重跑。
- 长时任务支持取消、进度、超时、资源限额和检查点；默认不得无限增长内存或静默丢弃数据。
- 算法选择以可测量的规模、稀疏度、精度和资源预算为依据；自动选择策略可解释，并允许用户锁定后端。
- 新增能力提供小型可运行示例、公开 API 文档、单元测试和端到端测试，不交付空函数或仅返回默认值的接口。

### 2.1 “达到成熟科学计算平台高度”的定义

“完整”不应理解为实现所有已发表算法或所有学科专用工具；这种范围没有可完成的边界。建议将目标定义为：常见科研与工程工作流有连贯、可组合的端到端实现；核心算法有可信验证和公开限制；专业领域能力可通过包/插件扩展；安装、脚本、数据交换、文档和版本演进可长期维护。

因此，阶段完成必须同时满足四个维度：

1. **覆盖**：功能矩阵中的基础任务有可用实现或明确的外部扩展接口，不以某个领域模块存在相似算法替代通用能力。
2. **正确**：有解析解、权威基准或可复现交叉验证；容差有误差预算依据。
3. **可用**：公开 API、示例、错误解释、数据输入输出和脚本调用构成可运行工作流。
4. **可持续**：性能/内存边界已知，支持矩阵有自动化测试，版本兼容和弃用规则有记录。

建议对每项能力标注成熟度，而不是只标“已实现”：**M0 规划、M1 原型、M2 验证、M3 稳定 API、M4 性能/互操作认证**。进入 M2 必须有正确性测试；进入 M3 必须有文档、错误契约和兼容承诺；进入 M4 必须有基准结果及支持平台/规模说明。

**矩阵使用规则：** 对每行分别记录“核心实现、可选适配器、明确不支持项、成熟度、基准证据、负责人/版本目标”。如果成熟替代库更合适，应优先提供可靠适配与统一错误/类型转换，而非维护质量较低的自研副本。算法命名相近不等于语义兼容，需逐项记录边界约定、默认参数、精度和输出形状。

### 2.3 达到目标的实施路线

1. **先做基线审计**：为矩阵每个能力域盘点源码、公开 API、测试、文档、第三方依赖许可/维护状态和性能；分别标注“可用、仅有框架、缺失、需替换”，不以文件名或蓝图标记推定实现完成。
2. **统一数值契约**：先确定 Scalar/复数/数组/稀疏矩阵/单位/错误/容差/随机种子/后端报告等跨模块规则，再向算法库和领域模块逐步迁移。
3. **锁定高频核心**：优先完善矩阵与稀疏系统、稳健方程求解、积分器与事件、优化/统计、信号分析、网格/PDE基础；长尾算法通过插件或适配器覆盖。
4. **构建工作流闭环**：从加载输入、校验模型、配置实验、运行/取消/恢复、检查结果和误差、导出/可视化到复现运行，至少提供一套可自动执行的示例项目。
5. **按成熟度发布**：只有达到 M3 的能力进入稳定公共 API；实验算法放在显式 experimental/feature 边界；移除或更改 API 时有弃用周期和迁移指南。
6. **用证据控制范围**：每个发布周期选择可完成的矩阵行和验收基准；公开缺口与支持矩阵，禁止以功能点总数或“全领域”口号替代质量证明。

### 2.4 顶层发布验收

- 一名新用户可在受支持平台按文档安装，运行示例、修改参数、执行批量/优化实验、查看图表并保存可重新读取的数据集。
- 对任一宣称稳定的算法，可查到定义清晰的输入/输出语义、前置条件、容差、复杂度/内存限制、错误状态和至少一个正确性基准。
- 关键工作流覆盖默认 CPU、可选加速后端、输入无效、算法不收敛、取消和 I/O 故障；任何失败都不会伪装成成功结果。
- 版本发布附带 API/平台/精度/格式支持矩阵、可复现实验结果、性能趋势与已知限制。
- 第三方包可独立添加扩展，不要求修改核心源码；扩展的版本冲突、来源、许可、失败边界和移除方式有清楚说明。

## 3. 阶段 35 — 稀疏线性代数与稳健数值计算

**目标：** 为有限元、有限体积、电路和大规模耦合方程提供适用于稀疏系统的可扩展计算路径，并补齐稠密计算中常见的最小二乘与秩判定能力。

### 3.1 建议模块

```text
src/core/compute/
  sparse/
    mod.rs
    matrix.rs            — COO/CSR/CSC 稀疏矩阵、校验与格式转换
    operations.rs        — SpMV、稀疏矩阵组合、稀疏向量运算
    iterative.rs         — CG、MINRES、GMRES、BiCGSTAB
    preconditioner.rs    — Jacobi、对角缩放、ILU(0) 等预条件器
    diagnostics.rs       — 残差、条件性估计、迭代统计和停止原因
  least_squares.rs       — QR/SVD 最小二乘、秩亏诊断
```

### 3.2 行为要求

- 稀疏矩阵构造拒绝越界索引、重复项处理策略不含糊，明确零值保留/消除规则，并校验矩阵维度及有限数值。
- COO、CSR、CSC 转换对空矩阵、空行、非方阵和重复坐标有明确测试；矩阵结构与数值数据分开暴露，方便重复装配。
- Krylov 求解器返回解向量及收敛统计，包括迭代次数、最终残差、停止原因、是否达到容差；达到迭代上限必须显式报告未收敛。
- 对称正定、对称不定和一般非对称系统分别校验求解器前置条件。错误算法/输入组合应返回具体错误，不静默切换到另一算法。
- 预条件器构造失败、对角元为零、分解失败等均有可定位错误。提供可选对角缩放，避免把缩放后的残差误当作原系统残差。
- 最小二乘支持过定、欠定、秩亏输入，明确解的约定，并输出秩/残差诊断；避免显式求逆形成正规方程作为通用默认实现。
- 后端调度要能报告实际执行路径；比较不同后端时同时检查误差界、NaN/Inf、内存分配和重复执行一致性。

### 3.3 验收

- 对随机生成且条件数可控的矩阵，检查解误差和归一化残差均低于配置阈值。
- 为对称正定、对称不定、非对称、奇异、近奇异和空系统分别覆盖预期成功/错误结果。
- 在至少一个代表性稀疏网格矩阵上，测试结果正确且内存增长随非零元数而非矩阵维数平方增长。
- 与现有稠密解法进行小规模交叉校验；性能测试只用于建立基线，不作为脆弱的固定毫秒级单测。

## 4. 阶段 36 — 灵敏度、参数估计、不确定性与优化

**目标：** 将现有参数扫描能力提升为可解释的实验设计和模型校准工作流。用户可以从测量数据估计参数、量化输入不确定性对输出的影响，并在明确约束下寻找可行设计。

### 4.1 建议模块

```text
src/
  analysis/
    mod.rs
    objective.rs          — 目标函数、观测量、权重及损失定义
    sensitivity.rs       — 局部有限差分灵敏度、扰动与归一化策略
    calibration.rs       — 参数估计、数据对齐、残差和拟合诊断
    uncertainty.rs       — Monte Carlo、拉丁超立方抽样、分位数区间
    optimization.rs      — 有界/无界单目标优化接口及算法实现
    experiment.rs        — 因子设计、样本计划与批次结果聚合
```

如当前 crate 分层不适合新增 `analysis/`，可将通用求解接口放入 `core/compute`，将具体仿真编排放入 `postproc`；须避免与 `postproc/batch.rs` 重复实现任务执行。

### 4.2 核心数据契约

- `ParameterSpec`：稳定参数路径、当前值、单位/量纲、边界、是否可估计、变换方式。
- `ObservationSet`：时间/空间采样位置、测量值、单位、标准差或权重、缺失值策略。
- `ObjectiveSpec`：输出映射、损失函数、权重、正则项及不可行结果策略。
- `AnalysisResult`：最优参数、目标值、约束状态、运行次数、收敛状态、误差/灵敏度摘要及每次仿真的可追溯 ID。

### 4.3 行为要求

- 初始交付使用无额外运行时依赖的有限差分灵敏度；导数近似必须记录步长、变量尺度和数值扰动策略。后续可增加伴随或自动微分，但不可将其作为首版前置条件。
- 校准前验证参数路径、单位兼容性、观测维度、时间戳顺序和缺失值；求解失败和数值发散作为分析结果中的显式失败样本，不伪造目标值。
- 优化提供有界参数处理、停止准则、迭代/评估上限、取消支持、约束违反信息和多起点可复现策略。
- 不确定性结果至少支持均值、标准差、指定分位数、置信区间和失败样本比例；抽样种子与抽样计划写入结果元数据。
- 多目标分析保存完整 Pareto 候选集与约束状态，不将单一加权分数伪装成唯一答案。
- 支持复用 `ParameterSweep` 的仿真执行和缓存能力；缓存键必须包含模型、参数、求解设置及依赖版本，不能只由参数值决定。

### 4.4 验收

- 以可解析的合成问题验证参数估计能恢复已知参数，并检查噪声增加时置信区间合理扩张。
- 用已知解析函数验证灵敏度符号、数量级和步长敏感性。
- 以含边界/约束的基准函数验证优化器满足约束、停止准则可重复、迭代上限会如实报告。
- 相同种子和配置重跑产生相同样本序列与相同汇总值；不同种子必须体现在元数据中。

## 5. 阶段 37 — 网格、边界区域与场数据工作流

**目标：** 把现有 STEP/STL/网格 I/O 连接到物理求解过程，定义可验证且不依赖特定领域的网格、区域、边界和场数据接口。

### 5.1 建议模块

```text
src/core/mesh/
  mod.rs
  topology.rs            — 节点、单元、单元类型、邻接关系
  region.rs              — 命名材料区、边界区及实体标签
  validate.rs            — 索引、退化单元、方向、连通性和质量检查
  field.rs               — 节点/单元/面上的标量、向量和张量场
  adapt.rs                — 误差指标、标记、细化/粗化与场转移接口
```

### 5.2 行为要求

- 建立网格公共契约：空间维数、单位/坐标系、节点 ID、单元类型、连通性、边界面、区域标签和来源信息。
- 网格读取器在导入时执行结构校验，返回元素/区域定位信息；不接受越界索引、无效维数、重复 ID 或退化单元而不提示。
- 网格质量指标按适用单元定义，至少报告零/负体积、极端长宽比和孤立区域；校验不能假定全部领域共用一个质量阈值。
- 边界条件引用稳定命名区域，不依赖导入文件中偶然的数组位置。缺失、重名或空区域必须在求解前检查。
- 场变量携带位置（节点/单元/面）、分量数、单位、时间戳和有效性信息；跨网格映射明确采用的方法、覆盖率和守恒误差。
- 自适应细化首版先提供统一误差估计/单元标记/细化器接口及至少一种结构网格或单元类型实现；场转移必须有可测的误差/守恒约束。
- 保持当前 STEP、STL 与通用网格读写 API 兼容；新旧格式转换均保留区域名称和坐标/单位元数据。

### 5.3 验收

- 对有效、空、损坏、退化、非流形及边界标签缺失的网格分别测试。
- 对恒定场、线性场和守恒量执行网格映射测试，验证误差及守恒偏差在声明阈值内。
- 对细化/粗化测试拓扑一致性、区域标签保留、字段映射和自由度数量变化。
- 每类新增网格单元至少有一个小型 fixture，避免依赖大型外部数据才能执行单测。

## 6. 阶段 38 — 可复现执行、检查点与弹性任务调度

**目标：** 让昂贵仿真可以安全暂停/继续、失败后恢复，并把现有批处理工作流扩展到受控的并发执行。

### 6.1 建议模块

```text
src/runtime/
  checkpoint/
    mod.rs
    format.rs             — 有版本号的检查点清单与载荷
    snapshot.rs           — 状态、事件队列、求解器历史及记录器快照
    compatibility.rs      — 模型/求解器/插件版本兼容性检查
  execution/
    mod.rs
    cancellation.rs       — 取消令牌与安全停止点
    resources.rs          — CPU、内存、GPU 和并发任务预算
    retry.rs              — 可配置重试、失败分类与退避策略
```

### 6.2 行为要求

- 检查点包含仿真时间、连续/离散状态、事件队列、随机数生成器状态、求解器内部历史、参数、模型图签名、库/插件版本和记录位置。
- 写检查点采用临时文件/目录后原子替换；写入中断不得破坏最后一个有效检查点。载入时校验 schema、哈希、版本和容量边界。
- 不兼容的状态必须拒绝恢复并说明差异；不得默默丢弃求解器历史或事件后声称从原位置无损继续。
- 仿真结果区分“正常结束、用户取消、资源限制、数值失败、I/O 失败和任务超时”，并保存最后一致状态。
- 资源调度对线程数、并发仿真数和设备选择设置明确上限；并行任务采用隔离的仿真上下文，不共享可变状态。
- 重试只对显式标记为可重试的失败启用；确定性输入错误和模型不收敛不得无限重跑。
- 分布式执行采用 transport/executor 抽象；首个里程碑实现本机多进程任务协议及可替换传输接口，不把某一特定集群设施写死在核心 API 中。

### 6.3 验收

- 在确定性模型中于多个时间点保存并恢复，比较最终状态、事件顺序和记录样本与不中断运行的结果。
- 模拟检查点截断、损坏、schema 新旧版本、不兼容插件和磁盘写入失败，确认返回明确错误且旧检查点可用。
- 验证取消信号能在安全步边界停止任务；资源预算超限不会影响其他并行任务状态。
- 注入暂时性任务失败验证有限重试；永久性输入错误确认不会被重试策略掩盖。

## 7. 阶段 39 — 自描述结果集、来源追溯与数据兼容

**目标：** 将仿真结果从“文件导出”升级为可组合、可查询、可审计且可长期读取的自描述数据集。此阶段增强既有 Recorder、Report 与 Exporter，不另造一套互不兼容的数据出口。

### 7.1 建议模块

```text
src/postproc/dataset/
  mod.rs
  schema.rs               — 结果变量、维度、坐标与单位描述
  manifest.rs             — 运行来源、版本、参数和校验摘要
  writer.rs               — 分块写入、压缩、追加及原子完成标记
  reader.rs               — 按变量、时间窗口和空间区域读取
  migration.rs            — 数据 schema 版本升级/兼容策略
```

### 7.2 行为要求

- 每个数据集提供版本化清单：仿真 ID、模型签名、运行配置哈希、参数及单位、求解器/容差、随机种子、后端、库/插件版本、创建时间、状态和错误摘要。
- 数据变量携带名称、物理量/单位、维度、采样位置、坐标轴、时间轴、缺测编码和精度。单位转换不得仅改显示标签而不变换数值。
- 支持分块追加写入和按时间/变量读取，写入失败可识别为不完整数据集；完成状态只能在所有区块及清单校验通过后提交。
- 文件格式实现分层：稳定的数据集 schema 与底层容器/压缩实现解耦；首版选择一种有良好 Rust 生态维护的容器即可，不要求同时实现多种容器。
- 既有 CSV/JSON/VTK/报告输出通过适配器导出或读取；导出不应成为唯一数据存储，并需明确表达不能保存的元数据。
- 敏感数据、私有库路径和环境信息可配置脱敏；不把密钥或本机凭据写进清单。

### 7.3 验收

- 端到端运行后生成可校验的数据集，关闭进程后重新打开，能够读取元数据、字段、时间窗及单位。
- 比较流式与一次性写入的结果，验证数据一致、列/变量集合完整且顺序有定义。
- 对写入中断、坏校验和不支持 schema 版本的情况报告失败，不返回看似成功的空结果。
- 对旧格式导出执行往返测试，并显式记录转换损失及不支持字段。

## 8. 阶段 40 — 数值验证、收敛研究与可信度基线

**目标：** 为核心求解器和领域模块建立统一的“结果是否可信”工作流，避免仅以代码能运行或测试不报错作为完成标准。

### 8.1 建议模块

```text
src/validation/
  mod.rs
  benchmark.rs            — 可版本化基准问题、参考结果与容差
  convergence.rs          — 时间步/网格细化研究与收敛阶估计
  invariants.rs           — 质量、能量、电荷、概率等领域可注册不变量
  comparison.rs           — 结果场对齐、误差范数和统计比较
  report.rs               — 机器可读验证结果与人类可读摘要
```

### 8.2 行为要求

- 区分单元测试、算法回归、物理基准和性能基准；参考结果附来源、单位、精度、适用范围及容差理由。
- 收敛研究可自动构造步长/网格序列，报告误差范数、观测阶、运行成本及是否进入渐近区；数据不足或不单调时不能捏造收敛阶。
- 结果比较先对齐单位、时间和网格；插值对齐造成的误差与求解误差分开报告。
- 不变量由领域显式注册，声明监测量、尺度、容差和允许的源汇项；不适用于某模型的不变量不能被全局强行启用。
- 后端对照覆盖 CPU 串行、CPU 并行及已启用的 GPU 路径；精度不同则报告精度等级和相对误差，不要求逐位相同。
- 记录求解器残差历史、拒绝步、事件定位误差、约束违反和发散告警，并将严重错误分类为可机器处理的错误码。
- 性能基准记录硬件/编译信息、问题规模、数据布局、线程数和峰值内存，允许趋势检测而非固定绝对时间门槛。

### 8.3 验收

- 每个核心求解器至少关联一个解析解问题和一个边界/异常问题。
- 代表性领域求解器至少具备一个网格或步长收敛测试、一个物理不变量测试及一个回归基准。
- 基准结果更新需审阅参考来源和误差预算，禁止通过任意放宽容差让失败测试变绿。
- 生成的验证摘要包含成功、失败、跳过及不适用项，不能把未执行项统计成通过。

## 9. 阶段 41 — 面向使用者的工具链、绑定与扩展兼容

**目标：** 让仿真库可以被非 Rust 使用者安装、自动化调用、部署和升级；让插件扩展在版本不匹配或运行异常时可诊断且有边界。

### 9.1 建议模块与交付物

```text
src/
  cli/
    mod.rs
    project.rs             — 项目配置检查、运行、状态与结果查询
    validate.rs            — 模型、库、插件和结果数据集校验命令
  bindings/
    c_api.rs               — 稳定 C ABI 外观层及错误码
    python/                 — 可安装的原生扩展、类型声明和包元数据
  bindings/plugins/
    compatibility.rs       — API 版本、能力声明及兼容策略
    diagnostics.rs         — 插件加载/初始化/运行故障上下文
```

具体实现可沿用现有目录结构，但公共接口须通过 `lib.rs` 有意重导出，避免内部模块布局直接成为永久承诺。

### 9.2 行为要求

- Python 绑定不仅提供 Rust 侧包装函数，还需建立可安装的原生包、异常映射、数值数组转换、生命周期/线程安全规则和最小可运行示例。
- C ABI 只暴露不透明句柄、固定宽度类型、明确的所有权释放函数和稳定错误码；不得跨边界传递 Rust `String`、trait object 或未定义布局结构体。
- CLI 至少支持项目配置检查、模型/输入校验、一次性运行、取消/恢复、运行状态查询及结果清单检查；参数错误和运行错误返回稳定非零退出码。
- 插件清单声明 API 版本、入口、能力、平台要求和依赖；加载前校验来源、签名/哈希策略及兼容性。动态库插件在进程内执行不应被描述为安全沙箱。
- 插件崩溃、初始化失败和符号缺失返回插件名、入口、版本、阶段及底层错误；禁止忽略加载错误后继续报告成功。
- 兼容策略采用版本化公共 API、弃用周期和迁移说明。不得因重排私有模块而破坏已有的公共路径。
- 文档示例按 CI 流程编译/运行；包发布对目标操作系统、架构、最低运行时和可选计算特性有明确矩阵。

### 9.3 验收

- 在干净环境中构建并安装 Python 包，运行示例完成建模、求解、结果读取和错误处理。
- 用独立 C 示例完成创建、执行、读取、释放全流程，并测试空句柄、错误配置和重复释放行为。
- CLI 的成功、输入错误、数值失败、取消和恢复分别验证退出码与机器可读状态。
- 插件版本不兼容、入口不存在、初始化报错及运行错误均可定位；失败插件不能污染其他插件或仿真全局状态。

## 10. 计算算法补充清单

本节针对“通用计算算法”本身补足 BLUE13 阶段 35~40 的实现范围。它不重复领域蓝图中的物理模型。已有能力（稠密 LU/QR/Cholesky、基础特征值、FFT、定步长/自适应/刚性 ODE、Newton-Raphson、基础数值求积及插值）作为起点；下列项目要求完善鲁棒性、规模适用范围和可验证性，不能仅因存在同名 API 就视为完成。

### 10.1 线性系统、特征值与大型问题算法

- **矩阵自由算子接口（P0）**：定义向量空间、维数、`apply`/`apply_transpose`、对角或块对角近似、稀疏结构提示等契约。Krylov 算法可直接消费算子，避免为有限元/有限体积系统强制构造完整矩阵。
- **Krylov 线性求解（P0）**：对称正定用 CG；对称不定用 MINRES；一般非对称用 GMRES（支持重启）和 BiCGSTAB。提供残差归一化、重启策略、迭代上限和明确的停止原因。
- **预条件与多重网格（P1）**：先实现 Jacobi、SSOR/不完全分解等局部预条件；随后提供几何多重网格和代数多重网格接口，涵盖平滑器、限制/延拓、粗网格求解及 V-cycle。须用网格加密实验验证迭代数增长，不得宣称线性复杂度而不提供证据。
- **谱算法（P1）**：为当前稠密子空间迭代补充 Lanczos（对称）与 Arnoldi（一般）部分谱分解；支持 shift-invert 的算子接口、残差收敛判据、重正交化和特征值聚簇测试。大矩阵不得先悄悄转为稠密矩阵。
- **分解与数值诊断（P1）**：补充秩揭示 QR/SVD（用于最小二乘和病态/秩亏判断）、条件数估计及迭代改进；对数值秩阈值、缩放策略和报告误差明确记录。
- **混合精度（P2）**：在硬件支持和问题条件允许时可用低精度因子分解/乘法并以高精度残差迭代校正；若校正不收敛则显式回退到受支持精度并记录，不得静默返回劣化解。

**验证指标：** 对各类矩阵核对原系统相对残差、解误差、停止原因和内存复杂度；对网格序列记录预条件前后迭代次数；特征对同时检查特征方程残差和正交性；病态/秩亏案例需验证诊断而不只检查返回向量。

### 10.2 非线性方程、根查找与约束问题

- **标量有界根查找（P0）**：二分法、Brent 类有界混合法和带保护的 Newton。零点是否被括定、区间端点、非有限函数值、区间缩小和函数评估上限均须明确定义。
- **全局化非线性求解（P0）**：在现有 Newton-Raphson 上增加阻尼/线搜索及信赖域策略；报告步长、残差范数、雅可比状态、迭代和失败原因，支持解析雅可比、有限差分雅可比及矩阵自由线性子问题。
- **非线性最小二乘（P1）**：Gauss-Newton 与 Levenberg-Marquardt，支持残差权重、参数缩放、边界、雅可比秩诊断和拟合协方差估计；稳健损失函数作为可选项并说明尺度参数含义。
- **拟牛顿与延拓（P2）**：Broyden 用于昂贵雅可比的非线性系统；参数延拓/同伦用于追踪解分支与改善初值敏感问题。保存分支、步长调整及折返点诊断。
- 所有求解器均要区分残差小、步长小、达到上限、停滞、奇异雅可比和用户取消；不能把“迭代停止”一律标成“收敛”。

**验证指标：** 使用多根、重根、无根、病态、初值远离解、非光滑和受约束标准问题，分别检查收敛/失败分类、残差、解精度及函数评估次数。

### 10.3 时间积分、DAE 与事件定位

- **高阶刚性积分（P1）**：在已有 BDF2 基础上规划可变阶 BDF（至少覆盖常见低阶稳定实现）及 Rosenbrock 类线性隐式方法；在选择范围内优先使用有清晰稳定性与误差估计的算法，避免仅增加方法名称。
- **隐式 Runge-Kutta（P2）**：对强刚性和高精度问题提供 Radau 类方法；需说明每步非线性/线性系统结构和代价。
- **连续延拓与稠密输出（P1）**：自适应 ODE 在已接受步内提供满足阶数要求的插值输出，供事件定位、指定输出时间和结果重采样使用，而不是额外强制缩小步长到每个记录时刻。
- **事件根定位（P1）**：过零事件使用步内插值和括区根查找定位事件时刻，支持方向、死区/滞回、同一时刻事件排序、重复触发抑制以及事件后的求解器历史重置。
- **DAE 健壮性（P2）**：记录约束残差和一致初值检查，明确 index-1 支持边界；高指数处理需经 index reduction 或显式拒绝并给出诊断，不能将一般 DAE 当作 ODE 隐式求解。
- **刚性检测（P2）**：用可解释的稳定步长/雅可比谱估计诊断刚性，并只提供建议或明确策略切换；自动切换需保护状态连续性并在结果中记录。

**验证指标：** 使用解析解、刚性基准方程、守恒系统、DAE 约束和事件时间有解析值的模型；进行步长/容差收敛试验，检查全局误差、约束残差、事件时刻误差和拒绝步统计。

### 10.4 数值微分、插值、频谱与卷积

- **数值微分（P1）**：有限差分支持前向/中心/五点模板、非等距采样和噪声影响说明；雅可比提供稀疏着色接口以减少函数调用。不要用未经误差评估的单一差分步长处理所有变量尺度。
- **自动微分（P2）**：先定义可组合的微分接口和受支持运算集合，再决定前向/反向模式实现；保证分支、非光滑算子和浮点异常的语义有说明。与有限差分、解析导数作交叉验证，不宣称对任意 Rust 闭包可自动微分。
- **插值（P1）**：在现有线性/样条基础上补充单调保形分段三次插值、张量积规则网格插值及散点数据插值接口；区分外推、超界错误和边界夹持，场重映射另行检查守恒误差。
- **FFT/谱分析（P1）**：补充任意长度 FFT 或明确报告长度约束、实数输入快速变换、逆变换归一化约定、窗口函数、Welch 功率谱密度、短时傅里叶变换和抗混叠重采样。频率轴、单边/双边谱、幅值/功率归一化须明确。
- **卷积与相关（P1）**：提供直接与 FFT 卷积/互相关路径，定义线性/循环卷积、边界补零、延迟索引和归一化；算法选择依据规模阈值并可由调用者指定。
- **抗混叠重采样（P2）**：降采样前滤波，支持非均匀时间戳输入的显式策略；对相位/幅值响应有基准测试。

**验证指标：** 使用多项式、解析导数、已知频率正弦、多音信号、脉冲卷积和边界信号验证误差、频率轴、能量/幅值归一化及相位。

### 10.5 随机数、统计与随机微分方程

- **可复现随机数生成（P0）**：统一 RNG trait/接口，随机种子和算法版本纳入运行元数据；并行分流使用可复现的子流派生，避免多个任务共享同一可变 RNG。
- **基础统计与稳健估计（P1）**：流式均值、方差、协方差、分位数/直方图、相关、bootstrap 区间和稳健汇总；声明样本不足和 NaN 处理行为。
- **随机采样（P1）**：覆盖均匀、正态及常用离散分布、重要性抽样和拉丁超立方；抽样质量通过边际分布、相关结构和收敛诊断检验。
- **随机微分方程（P2）**：Euler-Maruyama 起步，之后按需求实现 Milstein；噪声类型、Ito/Stratonovich 解释、步长依赖和随机收敛阶必须写入 API 及文档。
- **Monte Carlo 收敛（P1）**：提供置信区间、标准误、有效样本数或相应诊断、停止准则和最大样本数；不确定性分析不得只给点估计。

**验证指标：** 固定种子序列回归、分布矩/分位数统计检验、抽样方差随样本量趋势，以及 SDE 的强/弱收敛基准。

### 10.6 实施优先级

建议优先级按实际影响排序：

1. **P0：可信停止与基础稳健性** — 求解器统一状态/统计、括区根查找、全局化 Newton、确定性 RNG、矩阵自由算子/Krylov。
2. **P1：大规模和常用分析能力** — 预条件与多重网格、部分谱分解、非线性最小二乘、ODE 稠密输出/事件定位、网格与步长收敛、谱估计和插值完善。
3. **P2：高级方法** — 自动微分、延拓、隐式高阶积分、随机微分方程和混合精度。

每个算法实现前需先明确：适用问题类别、前置条件、误差估计、复杂度、内存需求、失败模式及对应基准。没有这些信息的“算法支持”不得作为完成项。

## 12. 全局质量门禁

所有阶段除本阶段验收项外，均需满足：

1. `cargo fmt --check`、`cargo clippy --all-targets -- -D warnings`、默认特性测试通过；可选 GPU 特性在对应设备/CI 环境单独验证。
2. 数值输入检查 NaN/Inf、空数据、形状不匹配、越界、零/负步长、非法容差和资源上限。
3. 错误类型带模块、操作、模型/任务 ID 和可恢复性；底层 I/O、后端、插件错误不可被空值、默认解或成功状态吞掉。
4. 所有新公共类型均有文档、示例和稳定序列化策略；内部状态不得无版本地持久化。
5. 默认路径保持 CPU 可用；可选功能缺少后端时明确失败或由用户显式选择 CPU 回退，并在结果元数据中记录实际路径。
6. 长任务可观测进度、取消状态、求解统计、资源使用和数据写入错误。
7. 领域数值结果只在验证范围内宣称适用；简化模型需明确假设、单位、适用区间和已知限制。
8. 维护者清单记录阶段状态、未覆盖测试、性能基线和已知限制，不能以“100%”替代可复现验收证据。

## 13. 明确不纳入本蓝图的事项

- 不重写已覆盖的 34 个阶段，也不为追求目录规模而重复实现已有领域模型。
- 不承诺单一接口能自动解决任意物理模型；各领域必须给出正确的方程、边界条件和验证证据。
- 不将所有数据永久驻留内存，不将任意插件视为可信，不在缺少能力探测时宣称 GPU/集群加速已生效。
- 不要求首个版本同时实现所有稀疏算法、所有文件格式、所有网格单元和所有优化策略；优先完成可测的基础子集，再按性能与用户需求扩展。
- 不把未验证的示例、参考值或未经说明的默认容差包装成工程认证结论。
