## Round 2: Issues Found During Deep Code Review

### 🔴 Issue 1: `engine.rs` — `unsafe` pointer used in stiff solver integration

**Location:** `src/runtime/solver/stiff.rs` (BackwardEuler, Trapezoidal)
**Severity:** Medium
**Description:** Stiff solvers use `*mut SolverStats` raw pointer to share statistics between closures:
```rust
let stats_ptr = &mut self.stats as *mut SolverStats;
// ...
unsafe { (*stats_ptr).function_evals += 1; }
```
This is technically safe in this single-threaded context but is a code smell that could be avoided with `std::cell::Cell`.

### 🔴 Issue 2: `workflow/engine.rs` — `WorkflowStatus::Failed` uses `&'static str`

**Location:** `src/runtime/workflow/engine.rs`
**Severity:** Low
**Description:** `Failed(&'static str)` restricts error messages to static strings. Should use `Failed(String)` or `Failed(SimError)` for runtime error messages.

### 🔴 Issue 3: `SequentialScheduler` has no ODE solver integration

**Location:** `src/runtime/scheduler/traits.rs` — `SequentialScheduler::step()`
**Severity:** Medium
**Description:** The `SequentialScheduler::step()` calls `execute_output_phase`, `propagate_signals`, `execute_update_phase`, and `execute_event_detection`, but does NOT call derivative computation or state integration. Per BLUE4 blueprint, the scheduler should orchestrate the full 8-phase cycle, but the ODE solver step is handled by the engine directly (not via scheduler).

### 🔴 Issue 4: `execute_output_phase` and `execute_update_phase` are no-ops

**Location:** `src/runtime/scheduler/hybrid.rs`
**Severity:** Low
**Description:** Both functions only validate that blocks exist but don't actually execute anything. The real execution happens in the engine. This is by design for the current architecture (engine owns `&mut Diagram`), but the doc-comments should clarify this.

### 🟡 Issue 5: Empty placeholder modules declared in mod.rs

**Locations:**
- `src/core/coord/mod.rs` — Phase 10 coordinate systems (comment only)
- `src/core/units/mod.rs` — Phase 11 units & dimensions (comment only)
- `src/runtime/algebraic/mod.rs` — Phase 8 algebraic loops (comment only)
- `src/blocks/mod.rs`, `src/bindings/mod.rs`, `src/coupling/mod.rs`, `src/db/mod.rs`, `src/domains/mod.rs`, `src/postproc/mod.rs`

These are architecturally declared but contain no code. They generate no warnings because `pub mod` declarations don't require non-empty modules.

### 🟡 Issue 6: `BackwardEuler` and `Trapezoidal` use `unsafe` for SolverStats sharing

**Severity:** Medium
**Description:** The `BackwardEuler::step()` creates a raw pointer `stats_ptr` and passes it to a closure that can't capture `&mut self.stats` directly due to borrow rules. Using `Cell<SolverStats>` would eliminate the `unsafe` block.

### 4.4 Bug Fix: `Diagram::compute_execution_order()`

**Issue:** `LinkSet::topological_sort()` only returns blocks that participate in links. Blocks with no links were excluded from the execution order, causing them to be invisible to the engine. This affected all engine operations on single-block or unconnected diagrams.

**Fix:** `Diagram::compute_execution_order()` now appends isolated blocks (present in diagram but absent from link graph) after the topologically sorted linked blocks.

**Impact:** Uncovered by new engine solver tests. All 376 tests pass after fix.
