## 二、numpy/MKL 风格计算优化（用户核心需求 3）

在 Session 1 的 `core/compute/backend.rs`（Serial/CpuParallel/Gpu 自适应 + GpuBackend 可插拔）基础上，
新增 **`core/compute/linalg.rs`** —— numpy.linalg / MKL 风格线性代数层：

| 类别 | 例程 | 对应 numpy/MKL |
|------|------|----------------|
| BLAS-1 | `scal` `nrm2` `asum` `iamax` `axpy` `dot` | `numpy.multiply/norm/…` |
| BLAS-2 | `gemv`（矩阵-向量） | `numpy.dot` 矩阵×向量 |
| LAPACK | `lu_decompose` `lu_solve` | `scipy.linalg.lu` / `solve`（dgetrf/dgesv） |
| LAPACK | `cholesky` | `numpy.linalg.cholesky`（dpotrf） |
| LAPACK | `qr_decompose` | `numpy.linalg.qr`（dgeqrf） |

- **自适应调度**：所有例程经 `AdaptiveCompute::kind_for(work_units)` 选择 Serial → CpuParallel(rayon) → Gpu；
  小负载串行避免开销，大负载多核并行，注册 GPU 后端后大负载自动走 GPU，无 GPU 透明回退 CPU。
- **单一事实来源**：`matrix::mat_vec_mul` → 自适应 `gemv`；`vector::dot`（大向量）/`vector::norm` → 自适应后端，
  消除重复的手写串行循环。
- **全局便捷 API**：`adaptive_scal/nrm2/asum/iamax/gemv/lu_solve/cholesky/qr` 已在 crate 根 `lib.rs` 重导出，
  可像 `np.linalg` 一样直接调用；GPU 为可插拔 `GpuBackend` trait（wgpu/OpenCL/CUDA/oneAPI 均可接入，无需改调用点）。
- **测试**：9 项（scal/nrm2/asum/iamax、gemv、2×2/3×3 LU 解并回验 A·x=b、奇异矩阵报错、Cholesky 往返、
  非正定报错、QR 往返 + Q 正交性），全部通过。

## 五、厂商 BLAS 加速（MKL / ACML / ESSL / cuBLAS）— 自适应选择（追加）

用户追加需求：计算库支持 **MKL / ACML / ESSL / cuBLAS** 加速，且**库的选择是自适应**。

### 新增模块 `core/compute/vendor_blas.rs`
- **`BlasVendor`** 枚举：`Mkl`(Intel/oneMKL, CPU)、`Acml`(AMD, CPU)、`Essl`(IBM, CPU)、`Cublas`(NVIDIA, GPU)
  - `is_gpu()`：仅 cuBLAS 为 GPU；`cpu_priority()`：自适应排序 MKL < ACML/ESSL；
  - `known_library_names()`：各厂商动态库探测名（libmkl_rt.so / libacml.so / libessl.so / libcublas.so…）；
  - `symbols()`：各厂商真实符号表（CBLAS `cblas_dgemm/dgemv/ddot/dnrm2/dasum/dscal/daxpy/idamax` + LAPACK `dgesv_/dpotrf_/dgeqrf_`；cuBLAS `cublasDgemm_v2…`）供 FFI 绑定直接使用。
- **`VendorBlasBackend`** trait：`gemm/gemv/axpy/dot/sum/scal/nrm2/asum/iamax/lu_solve/cholesky/qr`，
  默认返回 Err（未加速），由调度器统一 CPU 回退——绑定只需实现厂商实际加速的算子。
- **`detect_installed_vendors()`**：沿 `LD_LIBRARY_PATH/PATH` 及 `MKLROOT/ACML_DIR/ESSL_HOME/CUBLAS_HOME`
  探测已安装厂商库（纯文件系统探测，无链接依赖）。

### 自适应选择（backend.rs 集成）
- `BackendKind` 新增 **`VendorCpu`**。
- `AdaptiveCompute` 新增厂商注册表：`register_vendor_blas`（同厂商自动替换）/ `clear_vendor_blas` / `vendor_blases` /
  `best_vendor_cpu`（按 `cpu_priority` 选最优可用 CPU 厂商）/ `best_vendor_gpu`（cuBLAS）。
- `kind_for` 选择链：`force` → **Gpu**（超大负载 & GPU 后端或 cuBLAS 可用）→ **VendorCpu**（大负载 & 有可用 CPU 厂商）
  → `CpuParallel`(rayon) → `Serial`。即：**厂商库可用就用厂商库，否则自动降级多核/单核**。
- `mat_mul/gemv/axpy/dot/sum/scal/nrm2/asum/iamax/lu_solve/cholesky/qr` 全部接入 `vendor_or_cpu`：
  厂商支持 → 厂商库执行；厂商缺失/该算子不支持 → 透明回退内部 CPU（rayon/串行），结果与 CPU 完全一致。
- `describe()` 输出当前 `vendor_cpu=… / vendor_gpu=… / gpu=…` 供观测。

### 验证
- 新增测试 10 项：vendor 元数据/符号表、大负载选 VendorCpu、不可用厂商回退 rayon、cuBLAS 走 GPU 层、

## 六、真实加速落地：纯 Rust SIMD 内核（matrixmultiply）（追加）

针对上一节的诚实评估——厂商 BLAS 框架是"骨架"（无真实 FFI 绑定，任何机器上都回退 rayon，没有真实加速，
违反 principle.md 的"可观测行为变化"）——按推荐补足短板：**以纯 Rust SIMD 作为默认真实加速路径**。

### 新增依赖
- `matrixmultiply 0.3.11`（+transitive `rawpointer`）——BLIS 风格宏/微内核通用矩阵乘法，纯 Rust、

## 七、"各种计算"铺开：稠密 O(n³) 求解向量化 + 分块 Cholesky + LU 求逆（追加）

按用户目标"对各种计算增加 numpy/MKL 式优化"，用 `examples/compute_bench.rs`（release）对全部重算子

### 1) 标量内层循环向量化（纯安全代码，数学等价）
把 4 处 O(n³) 内层循环改为**快照枢轴行到临时 Vec + zip 迭代器**（消除源/目标切片别名疑虑，LLVM 自动向量化）：
- `linalg::lu_decompose`（影响 lu_solve/determinant 的尾部更新 axpy）
- `matrix::determinant`（其内联 LU 循环）
- `matrix::inverse`（高斯-约当行消元）
- `matrix::solve_linear`（高斯消元）
- `linalg::cholesky_cpu`（点积归约改 zip `.map().sum()`）

实测（release，best-of-reps）：lu_solve 256 **2.8→8.9 GFLOPS**、determinant 300 **3.1→10.7**、
solve_linear 300 **~3→8.8**、inverse 300 **1.5→3.7**、cholesky 256 **3.6→6.1**（1.7–3.4×）。

### 2) 分块 Cholesky（LAPACK dpotrf 式，真实 BLAS-3）
- 新增 `linalg::cholesky_blocked`（n ≥ 96 走分块，块宽 64）：
  1) 对角块标量 Cholesky；2) `trsm`：`L21 = A21·L11⁻ᵀ` 行向前代；3) `syrk`：`A22 ← A22 − L21·L21ᵀ`
  用新增 `simd::dgemm_strided`（α=−1, β=1 就地更新尾部块，无抽 A22/转置/回写拷贝）。
- `simd::dgemm_strided`：带步长（rs/cs）的安全 SIMD gemm 封装，仍属 simd.rs 唯一审计边界；
  步长非负 + 最高越界索引在安全代码内校验后才调用内核；`#[allow(too_many_arguments)]`（镜像 CBLAS 签名）。
- 块宽经验：64 优于 128（小/中规模面板开销占比）与 32（syrk 的 k 太瘦）。
- 实测：cholesky 512（分块+SIMD）**10.1 GFLOPS**（对照标量 ~6.5）；正确性经
  `test_cholesky_blocked_matches_reference`（96/110/128/160/200，含尾块 110=3×32+14）+ `_roundtrip` 双重验证。

## 八、补齐最后弱项：FFT twiddle 表 + 分块 CGS2 QR（追加，逐项收尾）

### 1) FFT twiddle 预计算（4×）
- 原蝶形内层每 (stage, j) 调 `cos()/sin()`（n·log₂n/2 次三角函数）。改为**预计算 twiddle 表**
  （n/2 个 n 次单位根，一次三角计算），各级按 `step = n/len` 步长索引 `tw[j·step]` —— 内层零超越函数。
- 数值精度不变（表值精确，非增量累积）；`ifft`/`power_spectrum` 共用 `fft` 自动受益。
- 实测：fft 65536 **1.2→4.8 GFLOPS（4×）**（含测试 8 项通过）。

### 2) QR：转置 MGS 向量化（1.7×）+ 分块 CGS2（6×）
- `qr_cpu`（参考）改为**转置存储 Qᵀ（n×m）**：MGS 的 dot/axpy 内层沿连续 m 向量，自动向量化。
  → 320×320 **3.1→5.3 GFLOPS**。
- 新增 **`qr_blocked`**（n,m≥32 且 work≥20000 走分块，块宽 32）：逐块
  1) 投影 `R=Qᵀ·A_block`、`V=A_block−Q·R_block` 均为 `simd::dgemm_strided`（BLAS-3）；
  2) 块内 **CGS2**（两次再正交化，保正交性到机器精度）。
  → 320×320 **5.3→18.6 GFLOPS（合计 6×）**；测试对参考 + Q·R=A + QᵀQ=I
  （140/150/160×90/100×64，含尾块 150=4×32+22）。

### 验证
- 新增测试 1 项（分块 QR 多尺寸对参考/往返/正交）。
- 全项目：`cargo test` **1870 lib + 2 doc tests, 0 failed / 0 ignored**；`cargo clippy --all-targets -D warnings` 0 警告。
- 综合基准收尾：**每个重算子现在都有真实、可观测的加速路径**（mat_mul SIMD/并行、gemv SIMD、
  BLAS-1 自适应、LU/Cholesky 向量化、QR 分块 CGS2、inverse LU、FFT twiddle）。

### 负结果（诚实记录，符合 principle.md）
- 尝试给分块 Cholesky 的 syrk 接并行 gemm（`dgemm_parallel`：连续临时缓冲 + 回写，rayon 行分块）：
  cholesky 512 **11.7→4.5 GFLOPS 回退**——syrk 是瘦 gemm（k=块宽 64），并行启动 + O(m²) 拷贝开销
  超过多核收益。已回退为更快的就地 strided 串行版并删除该实验代码。结论：瘦 gemm 不宜并行，
  分块稠密算法要保持块宽内的单核 SIMD 高效。

## 十二、BLUE1~12 全项目计算扫描：剩余热点多轮加速（追加，12 项，2026-07-31）

用户要求以 BLUE1~12 涉及的计算为纲，全项目扫描"还能加速的"（并行 / CPU SIMD / GPU），多轮全方位分析后逐一加速。
先读全部 12 份蓝图 + principle + roadmap 建立计算清单，再逐文件核查热点；对每个候选判断"是否热点/能否安全并行/如何加速"。

### 已实现（3 轮，共 12 项，全部带阈值守卫 + 并行 vs 串行参考测试）
**Round 1（易并行扫描/步进，10 项）**
1. analog `run_ac_sweep`/`run_dc_sweep` — 每扫描点独立 MNA 求解 → rayon（保序索引 collect；`PAR_MIN_STEPS/POINTS=8`；签名加 `+ Sync`，调用方均为 Sync 闭包）。
2. tcad `mosfet_iv_curve`/`bjt_iv_curve` — 每偏置点独立器件求值 → rayon 扁平索引（`IV_PAR_MIN_POINTS=2048`）。
3. astrophysics MHD `step()` — 两个通量扫描只写克隆 U_new、只读 self.U → rayon 按行（y 向边界行守卫）。
4. bio_medical `tissue_diffusion::step()` — 逐格 Laplacian+源，读不可变快照写 new_conc → rayon 按行；非负回写 zip 并行。
5. structural `explicit_dynamics::step()` — 对角质量/阻尼逐 DOF 独立 → rayon 三趟（u_next / v / a 各 par_iter）。
6. optical `trace_fan`+`defocus_spot` — 逐光线独立 → rayon `filter_map`（保序）/ `max_by` 归约（阈值 256/512）。
7. multibody `assemble_eom()` — 逐刚体独立（只读 self.forces/gravity）→ rayon 保序 map+collect（顺带删除未用 `_id_map`）。
8. molbio `docking` `shape_score`/`electrostatic_score` — 逐配体归约 → rayon `sum()`（`PAR_MIN_PAIRS=16384`；浮点重排用 1e-9 相对容差测试）。
9. thermal `radiation_3d::solve()` 重置 + 辐射热源两趟 → rayon（热源趟用温度/入射预绑定引用避免字段借用冲突；方向扫描上风顺序依赖保持串行）。
10. postproc `optimize_grid` — 逐迭代独立目标 → rayon `min_by`（obj,params）归约（`PAR_MIN_ITERS=1024`）。
**Round 2（BEM 装配，1 项）**
11. acoustic `bem_acoustic::surface_pressure` — G/H 装配：每单元只写 3×3 节点块 → **每单元偏量并行 + 串行归约**（`PAR_MIN_ELEMENTS=256`，避免共享矩阵竞争）；RHS 逐行独立 → rayon 按行。结果与串行逐位一致（逐单元独立 + 串行归约）。
**Round 3（腔体模态，1 项）**
12. acoustic `rectangular_room_modes` — O(nx·ny·nz) 模态枚举，每模态独立 → rayon 扁平索引 + filter + 排序（`PAR_MIN_MODES=1024`）。

### 分析后诚实跳过（本轮不加速）
- `quantum/lindblad` 手写复数稠密乘：dim³ 通常 <4096，路由 `mat_mul_complex` 反增拆分开销 → 跳过（apply_kraus 已路由）。
- `cellbio/cell_model::update`：分裂配额（`initial_count+new_cells.len()<max_cells`）与 ID 分配跨格耦合，逐细胞并行需重设计 → 后续。
- `radiation_3d` DOM 方向扫描：上风顺序依赖（类 Gauss-Seidel），并行改数值 → 保持串行。
- `thermal/conduction` 2D SOR / `emag/static_fields` 1D Gauss-Seidel：就地迭代本质串行 → 跳过。
- `digital/timing` 关键路径：顺序最长路径算法 → 跳过。
- ODE 求解器（Euler/RK4）AXPY 向量更新：n 适中且 f()（用户回调）主导不可并行 → 跳过。
- 已并行/已路由（核查确认无需再动）：MNA `solve`→`solve_linear`、fem_solver 刚度装配 rayon、FDTD 3D rayon、runtime `solve_linear_dense`→core、field_mapping rayon、quantum gate apply→mat_vec_mul_complex。
