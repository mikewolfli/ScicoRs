## 二、numpy/MKL 风格计算优化（用户核心需求 3）

在 Session 1 的 `core/compute/backend.rs`（Serial/CpuParallel/Gpu 自适应 + GpuBackend 可插拔）基础上，
新增 **`core/compute/linalg.rs`** —— numpy.linalg / MKL 风格线性代数层：

| 类别 | 例程 | 对应 numpy/MKL |
|------|------|----------------|
| BLAS-1 | `scal` `nrm2` `asum` `iamax` `axpy` `dot` | `numpy.multiply/norm/…` |
| BLAS-2 | `gemv`（矩阵-向量） | `numpy.dot` 矩阵×向量 |
| LAPACK | `lu_decompose` `lu_solve` | `scipy.linalg.lu` / `solve`（dgetrf/dgesv） |
| LAPACK | `cholesky` | `numpy.linalg.cholesky`（dpotrf） |
| LAPACK | `qr_decompose` | `numpy.linalg.qr`（dgeqrf） |

- **自适应调度**：所有例程经 `AdaptiveCompute::kind_for(work_units)` 选择 Serial → CpuParallel(rayon) → Gpu；
  小负载串行避免开销，大负载多核并行，注册 GPU 后端后大负载自动走 GPU，无 GPU 透明回退 CPU。
- **单一事实来源**：`matrix::mat_vec_mul` → 自适应 `gemv`；`vector::dot`（大向量）/`vector::norm` → 自适应后端，
  消除重复的手写串行循环。
- **全局便捷 API**：`adaptive_scal/nrm2/asum/iamax/gemv/lu_solve/cholesky/qr` 已在 crate 根 `lib.rs` 重导出，
  可像 `np.linalg` 一样直接调用；GPU 为可插拔 `GpuBackend` trait（wgpu/OpenCL/CUDA/oneAPI 均可接入，无需改调用点）。
- **测试**：9 项（scal/nrm2/asum/iamax、gemv、2×2/3×3 LU 解并回验 A·x=b、奇异矩阵报错、Cholesky 往返、
  非正定报错、QR 往返 + Q 正交性），全部通过。

## 五、厂商 BLAS 加速（MKL / ACML / ESSL / cuBLAS）— 自适应选择（追加）

用户追加需求：计算库支持 **MKL / ACML / ESSL / cuBLAS** 加速，且**库的选择是自适应**。

### 新增模块 `core/compute/vendor_blas.rs`
- **`BlasVendor`** 枚举：`Mkl`(Intel/oneMKL, CPU)、`Acml`(AMD, CPU)、`Essl`(IBM, CPU)、`Cublas`(NVIDIA, GPU)
  - `is_gpu()`：仅 cuBLAS 为 GPU；`cpu_priority()`：自适应排序 MKL < ACML/ESSL；
  - `known_library_names()`：各厂商动态库探测名（libmkl_rt.so / libacml.so / libessl.so / libcublas.so…）；
  - `symbols()`：各厂商真实符号表（CBLAS `cblas_dgemm/dgemv/ddot/dnrm2/dasum/dscal/daxpy/idamax` + LAPACK `dgesv_/dpotrf_/dgeqrf_`；cuBLAS `cublasDgemm_v2…`）供 FFI 绑定直接使用。
- **`VendorBlasBackend`** trait：`gemm/gemv/axpy/dot/sum/scal/nrm2/asum/iamax/lu_solve/cholesky/qr`，
  默认返回 Err（未加速），由调度器统一 CPU 回退——绑定只需实现厂商实际加速的算子。
- **`detect_installed_vendors()`**：沿 `LD_LIBRARY_PATH/PATH` 及 `MKLROOT/ACML_DIR/ESSL_HOME/CUBLAS_HOME`
  探测已安装厂商库（纯文件系统探测，无链接依赖）。

### 自适应选择（backend.rs 集成）
- `BackendKind` 新增 **`VendorCpu`**。
- `AdaptiveCompute` 新增厂商注册表：`register_vendor_blas`（同厂商自动替换）/ `clear_vendor_blas` / `vendor_blases` /
  `best_vendor_cpu`（按 `cpu_priority` 选最优可用 CPU 厂商）/ `best_vendor_gpu`（cuBLAS）。
- `kind_for` 选择链：`force` → **Gpu**（超大负载 & GPU 后端或 cuBLAS 可用）→ **VendorCpu**（大负载 & 有可用 CPU 厂商）
  → `CpuParallel`(rayon) → `Serial`。即：**厂商库可用就用厂商库，否则自动降级多核/单核**。
- `mat_mul/gemv/axpy/dot/sum/scal/nrm2/asum/iamax/lu_solve/cholesky/qr` 全部接入 `vendor_or_cpu`：
  厂商支持 → 厂商库执行；厂商缺失/该算子不支持 → 透明回退内部 CPU（rayon/串行），结果与 CPU 完全一致。
- `describe()` 输出当前 `vendor_cpu=… / vendor_gpu=… / gpu=…` 供观测。

### 验证
- 新增测试 10 项：vendor 元数据/符号表、大负载选 VendorCpu、不可用厂商回退 rayon、cuBLAS 走 GPU 层、

## 六、真实加速落地：纯 Rust SIMD 内核（matrixmultiply）（追加）

针对上一节的诚实评估——厂商 BLAS 框架是"骨架"（无真实 FFI 绑定，任何机器上都回退 rayon，没有真实加速，
违反 principle.md 的"可观测行为变化"）——按推荐补足短板：**以纯 Rust SIMD 作为默认真实加速路径**。

### 新增依赖
- `matrixmultiply 0.3.11`（+transitive `rawpointer`）——BLIS 风格宏/微内核通用矩阵乘法，纯 Rust、
  std::arch 运行时检测 x86-64 AVX2/FMA/AVX-512 与 aarch64 NEON，零 C 依赖，**与 ndarray 同一内核**。

### 新增模块 `core/compute/simd.rs` —— 全 crate 唯一经审计的 unsafe 边界
- `matrixmultiply::dgemm` 为 `unsafe fn`。为守住"生产代码零 unsafe"原则，把**唯一一处** unsafe 调用
  封装进该模块的安全 API `dgemm` / `dgemv`，并在**安全代码内**先验证全部不变量：
  维度非空、`a.len()>=m·k`、`b.len()>=k·n`、`c.len()>=m·n`、行主序步长 `rs=#cols, cs=1`、`c` 为新建缓冲无别名。
  断言在 release 也生效 → unsafe 仅在形状被内核接受时才被触达（与 ndarray 封装同一内核的做法一致）。
- `#[cfg(test)]` 两项：`dgemm`/`dgemv` 与标量参考逐元素比对（误差 < 1e-9）。

### 热路径接线（真实加速生效）
- `matrix::mat_mul`：≥4096 work units 走 SIMD（`simd::dgemm`），小问题保留朴素 `ikj` 参考（避免启动开销）；
  原朴素实现改名为 `mat_mul_naive`（pub，供测试/基准对比）。
- `matrix::mat_mul_parallel`：rayon 按 64 行分块，每块调 SIMD 内核 → **SIMD × 多线程**。
- backend.rs：`CpuParallel`/`VendorCpu` 回退路径改用 `matrix::mat_mul_parallel`；`Serial` 用 `mat_mul`（内部 SIMD）。
- `linalg::gemv`：大负载把 `A·x` 当作 `m×k @ k×1` 的 BLAS-3 gemm 走 `simd::dgemv`（SIMD 加速 BLAS-2）。

### 可观测验证（`examples/matmul_bench.rs`，release，512³ f64）
```
naive (reference)              87.1 ms       3.08 GFLOPS
SIMD (matrixmultiply)           8.2 ms      32.73 GFLOPS   → 10.6×
SIMD + rayon (parallel)         4.5 ms      59.99 GFLOPS   → 19.5×
max |Δ| SIMD = SIMD+rayon = 6.0e-14（浮点等价）
```
