## 第三轮：统一计算平台方案

### 3.1 现状分析

当前项目的计算架构特征：
- **纯 Rust 实现** — 无外部科学计算依赖（无 ndarray/nalgebra/faer）
- **手动矩阵运算** — 所有矩阵操作（乘法、消元、求逆）在各模块中手动实现
- **单线程执行** — 无任何并行计算库（无 rayon/tokio/async）
- **统一类型系统** — 全部使用 `Scalar = f64`，类型一致性是优势

### 3.2 统一计算平台方案

建议建立三个层次的计算平台：

```
                  ┌─────────────────────────────────────┐
                  │      Layer 3: 领域专用计算器         │
                  │  FemSolver | NavierStokes2D | MNA    │
                  │  QuantumSolver | NBodySolver 等      │
                  └──────────────┬──────────────────────┘
                                 │ 调用
                  ┌──────────────v──────────────────────┐
                  │  Layer 2: 通用科学计算 API           │
                  │  core/compute/ 模块                  │
                  │  - 矩阵运算 (mul/inv/det/solve)      │
                  │  - 向量运算 (dot/cross/norm/interp)  │
                  │  - FFT/数值积分/微分                 │
                  │  - 稀疏矩阵支持                       │
                  └──────────────┬──────────────────────┘
                                 │ 调用
                  ┌──────────────v──────────────────────┐
                  │  Layer 1: 基础线性代数原语           │
                  │  core/tensor.rs (增强)               │
                  │  + core/types.rs (Scalar 类型)       │
                  │  + runtime/solver/ OdeSolver trait   │
                  └─────────────────────────────────────┘
```

### 3.3 并行化计算方案

当前所有计算是纯单线程的。引入并行化有三个层次：

#### 层次 1：数据并行（低风险，高回报）

使用 `rayon` crate 将独立循环自动并行化：

| 位置 | 循环类型 | 并行化潜力 |
|------|---------|-----------|
| `runtime/workflow/parallel.rs` | 任务调度 | **极高** — 同一 stage 内的任务天然独立 |
| `structural/fem_solver.rs` | 单元刚度矩阵组装 | **高** — 每个单元独立 |
| `fluid/navier_stokes.rs` | 网格点更新 | **高** — 空间离散点独立 |
| `molbio/dynamics.rs` | 原子力计算 | **高** — 原子间力独立 |
| `domains/*/analysis.rs` | 批量数据分析 | **中** — 取决于数据量 |
| `runtime/engine.rs` | 引擎主循环 | **低** — 串行依赖强 |

**建议：** 添加 `rayon = "1"` 到 Cargo.toml，在 `workflow/parallel.rs` 中率先引入并行执行，优先加速 FEA 刚度矩阵组装和 CFD 网格更新。

#### 层次 2：任务并行（架构已有基础）

`runtime/workflow/` 已有完整的任务 DAG + 阶段分解 + barrier 同步架构，但 `ParallelScheduler::execute_stage()` 当前使用顺序 `for` 循环。将并行调度器改为使用 `rayon::scope` 或 `rayon::join_all` 即可获得并行加速。

#### 层次 3：流水线并行（远期目标）

多物理场耦合（阶段 30~34 完成后）的不同物理场可在各自 CPU 核心上异步推进，在耦合点同步。这需要 `coupling/` 模块实现后才能落地。
